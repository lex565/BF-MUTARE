# 07 — Rider onboarding

Rider signup reuses the existing Supabase login and application `users` row. A
public application may submit only basic operational and vehicle information.
It cannot grant the `RIDER` role or activate delivery privileges.

Lifecycle:

`APPLICATION → UNDER_REVIEW → VERIFICATION_COMPLETE → CONTRACT_CONFIRMED → APPROVED → ACTIVE`

Management may also set `REJECTED`, `RESTRICTED`, `SUSPENDED`, or `INACTIVE`.
Every change needs a reason and creates both a rider status event and an audit
entry. Suspension immediately removes the `RIDER` role. Reactivation requires
a verified status and a configured trust level.

Public rider numbers are generated by Postgres as `MUR-R-0001`, while UUIDs
remain internal.

Sensitive verification is deliberately disabled. With
`ENABLE_SENSITIVE_RIDER_VERIFICATION=false`, neither the API nor mobile UI asks
for national ID or police/background documents. Legal approval, a retention
policy, private storage, access logging, and an authorized reviewer workflow
are required before enabling that work.
